## 1. 이번 주 학습 주제

> 커버트 채널·사이드 채널을 이해하기 위한 기반 개념 학습 — 접근제어와 정보흐름 제어의 차이, Bell-LaPadula/Biba/non-interference 보안 모델, Lampson의 격리(confinement) 문제와 커버트 채널의 원조 정의, 커버트 채널과 사이드 채널의 판별 기준, 저장 채널과 타이밍 채널의 2분류, Shared Resource Matrix를 이용한 채널 식별, Shannon 채널 용량으로 대역폭을 산정하는 법, 그리고 이 모든 논의의 물리적 근거인 메모리 계층과 자원 공유 구조

## 2. 학습 내용 요약

### (황준하) 정보흐름(Information Flow) 보안 모델

- **접근제어(access control)와 정보흐름 제어(information flow control)의 차이**. 접근제어는 "누가 무엇을 열 수 있는가"만 통제하고, 한 번 열람한 주체가 그 정보를 어디로 흘리는지는 통제하지 못한다. 커버트 채널은 정확히 이 빈틈에 존재한다.
- **Bell-LaPadula(BLP)** — 기밀성(confidentiality) 중심의 다중등급 보안(MLS) 모델.
  - *Simple Security Property (no read up)*: 낮은 등급 주체는 높은 등급 객체를 읽을 수 없다.
  - *\*-Property (no write down)*: 높은 등급 주체는 낮은 등급 객체에 쓸 수 없다 — 정보가 아래로 흐르는 것을 막는 규칙.
- **Biba** — 무결성(integrity) 중심으로 방향이 정확히 반대다(no read down / no write up). 기밀성 모델과 무결성 모델이 서로 반대 방향의 흐름을 막는다는 대칭 구조를 확인했다.
- BLP가 통제하는 것은 **명시적(overt) 채널**뿐이다. High 등급 프로세스가 파일에 쓰지 않고도 *자원의 상태를 바꾸는 것만으로* Low 등급 프로세스에게 신호를 보낼 수 있고, 이때 BLP의 두 규칙은 전혀 위반되지 않는다. 이것이 커버트 채널이 성립하는 지점이다.
- **Non-interference** (Goguen & Meseguer, 1982) — "High의 행동이 Low가 관측하는 시스템 상태에 아무 영향도 주지 않아야 한다"는 더 강한 형식적 요구. 커버트 채널의 존재는 곧 non-interference 위반이며, 자원을 공유하는 실제 시스템에서 이 성질을 완전히 만족시키는 것은 사실상 불가능하다.

### (황준하) Lampson의 격리 문제 — 커버트 채널의 정의

- **Butler Lampson, "A Note on the Confinement Problem" (CACM, 1973)** 을 정독했다. 문제 설정은 "빌려온(untrusted) 프로그램에게 내 데이터를 처리시키되, 그 프로그램이 데이터를 밖으로 못 흘리게 가둘 수 있는가?"
- Lampson이 분류한 유출 경로:
  1. **정당한 채널(legitimate channel)** — 프로그램의 정상 출력(계산 결과 등).
  2. **저장 채널(storage channel)** — 프로그램이 남긴 흔적을 통한 전달(파일 존재 여부, 락 상태 등).
  3. **커버트 채널(covert channel)** — 정보 전달용으로 **설계되지 않은** 메커니즘을 통한 전달. 원문의 예시가 인상적이다: *"프로세스가 CPU 사용량을 조절해서 다른 프로세스에게 신호를 보낼 수 있다."*
- 정리하면 **커버트 채널 = 시스템의 보안 정책이 허용하지 않는 방향으로, 통신용으로 의도되지 않은 메커니즘을 통해 정보를 전달하는 채널.**

### (황준하) 커버트 채널과 사이드 채널의 판별 기준

두 용어가 문헌마다 혼용되어 초반에 계속 헷갈렸는데, **송신 측의 의도(intent)** 를 기준축으로 잡으니 정리가 됐다.

| 구분 | 커버트 채널 | 사이드 채널 |
|---|---|---|
| 송신자 | **존재하며, 의도적으로 정보를 흘린다**(내부자 / 감염된 프로세스 / 신뢰할 수 없는 코드) | **존재하지 않는다.** 피해자는 정상 동작 중이며 신호를 보낼 의도가 없다 |
| 정보원 | 송신자가 인위적으로 변조한 자원 상태 | 연산의 물리적·구조적 **부산물**(시간, 전력, 캐시 상태, 전자기파) |
| 참여자 | 2자 통신(송신자 + 수신자) | 1자 관측(공격자만 능동) |
| 위협 | 데이터 유출(exfiltration), 격리·에어갭 우회, MLS 정책 위반 | 비밀키 복구, 프라이버시 침해, 격리 경계 침범 |
| 예 | DNS 터널링, 팬 소음 유출, 파일 락을 이용한 비트 전송 | 캐시 타이밍으로 AES 키 추출, 전력분석 |

- 중요한 것은 두 개념이 **기술적으로는 같은 메커니즘을 공유**한다는 점이다. 사이드 채널 관측 기법은 커버트 채널의 *수신부*로 그대로 재활용된다. 즉 캐시 타이밍 측정 기술 하나가 양쪽 모두의 기반이 된다.
- 인접 개념과의 구분도 정리했다. 명시적 취약점(SQLi, 버퍼오버플로)은 채널이 아니라 정책 자체의 결함이고, **스테가노그래피**는 "채널은 합법적이되 내용이 숨겨진" 경우라 층위가 다르다(다만 네트워크 스테가노그래피는 실질적으로 커버트 채널과 겹친다).

### (황준하) 저장 채널 vs 타이밍 채널

TCSEC 이래 표준이 된 2분류이며, 판정 기준은 **"수신자가 시계(clock)를 필요로 하는가"** 다.

- **저장 채널(Storage Channel)**: 송신자가 공유 자원의 *속성값*을 바꾸고 수신자가 그 값을 직접 읽는다. 시계가 필요 없다.
  - 예: 파일 존재 여부, 디스크 여유 블록 수, 프로세스 테이블 엔트리 개수, 파일 락 상태, exit code, `errno` 값.
- **타이밍 채널(Timing Channel)**: 송신자가 *자원을 점유하는 시간*을 변조하고, 수신자가 자기 진행 속도의 변화를 시계로 측정한다.
  - 예: CPU 스케줄링 quantum 소진 여부, 버스·메모리 컨트롤러 경합, 디스크 암(arm) 위치.
- 경계가 흐린 사례가 많다. 캐시 점유 상태는 "저장"에 가깝지만 그것을 읽어내는 수단이 접근 지연시간이라 "타이밍"이기도 하다 → 문헌에서는 관측 수단을 기준으로 **타이밍 채널로 분류**하는 것이 일반적이다.
- 이 밖에 **종료 채널(termination channel)**, **자원 고갈 채널**, **전력·열 등 물리 채널**을 별도로 언급하는 문헌도 있으나 대개 위 둘의 하위분류로 정리된다.

### (황준하) 채널 식별 방법론 — Shared Resource Matrix

- **TCSEC(오렌지북, DoD 5200.28-STD)** 이 커버트 채널 분석을 실무 요구사항으로 만들었다.
  - **B2**: 커버트 *저장* 채널을 식별하고 대역폭을 산정할 것.
  - **B3 / A1**: 커버트 *타이밍* 채널까지 포함, A1은 형식적 검증까지.
  - 관례적 기준선: **100 bps 초과는 위험**, **0.1 bps 미만은 통상 무시 가능**, 그 사이는 감사 대상. 절대 기준이 아니라 당시 시스템 성능에 근거한 관례라는 점에 유의.
- **Shared Resource Matrix (SRM)** — Kemmerer(1983). 행에 공유 자원의 속성, 열에 연산(operation)을 두고 각 칸에 `R`(참조) / `M`(변경)을 표기한다. **"Low가 R할 수 있고 High가 M할 수 있는 속성"** 이 곧 잠재적 커버트 채널 후보다.
  - 직접 파일시스템 속성을 대상으로 행렬을 그려봤고, 후보 채널 3건(파일 존재 여부, 잔여 블록 수, 락 상태)을 도출했다. 기법 자체는 단순하지만 "빠짐없이 훑는다"는 점에서 지금도 유효하다.
- 그 밖의 접근: non-interference 기반 형식 분석, 정보흐름 타입 시스템(코드 레벨에서 High→Low 흐름 정적 차단), Covert Flow Tree.

### (황준하) 채널 용량(capacity) 산정 — 정보이론 적용

커버트 채널을 Shannon의 잡음 있는 통신 채널로 모델링해 대역폭을 정량화하는 방법을 학습했다.

- 이진 대칭 채널(BSC)로 근사하면 심볼당 용량은
  `C = 1 - H(p)`, `H(p) = -p·log₂p - (1-p)·log₂(1-p)`
  여기서 `p`는 비트 오류율, `H`는 이진 엔트로피 함수.
- 초당 용량은 `C_bps = C / T_symbol`.
- 직접 계산해 본 값: `p=0.01 → C≈0.919`, `p=0.05 → C≈0.714`, `p=0.11 → C≈0.500`, `p=0.5 → C=0` (완전 잡음, 채널 소멸).
- 여기서 공격자와 방어자가 다투는 두 변수가 정의된다. **공격자는 오류율 `p`를 낮추거나 심볼 주기 `T`를 줄여 대역폭을 올리려 하고, 방어자는 잡음을 주입해 `p`를 0.5 쪽으로 밀거나 시계 해상도를 낮춰 `T`의 하한을 올린다.**

### (황준하) 자원 공유 구조와 메모리 계층

이후 다룰 캐시·타이밍 공격의 물리적 근거가 되는 배경을 정리했다.

- **프로세스 격리의 실체**: 가상주소공간 분리, 유저/커널 링, 시스템 콜 경계. 즉 격리되는 것은 *주소공간*이지 *마이크로아키텍처 상태*가 아니다. 이 비대칭이 사이드 채널 전체의 출발점이다.
- **메모리 계층과 접근 지연**: 레지스터 → L1(≈4 cycle) → L2(≈12) → L3/LLC(≈40) → DRAM(≈200~300 cycle). 계층 간 지연 격차가 크다는 사실 자체가 **접근 시간을 관측 가능한 신호로 만든다.**
- **공유되는 자원의 층위**: CPU 코어와 SMT 스레드, 캐시(특히 코어 간 공유되는 LLC), TLB, 분기예측기, 메모리 컨트롤러와 버스, 스토리지, 네트워크 스택, 전원과 발열. 층위마다 별도의 채널이 존재한다.
- **멀티테넌시 맥락**: 클라우드·컨테이너 환경에서는 위 층위 대부분이 테넌트 경계를 가로질러 공유된다. 1973년의 문제 설정이 지금 다시 중요해진 이유가 여기 있다.

## 4. 주요 논의 / Q&A

- **커버트 채널과 사이드 채널을 구분하는 실익.** 방어 설계가 달라진다. 커버트 채널은 *이미 시스템 안에 악의적 송신자가 있다*는 전제에서 출발하므로 대응이 "대역폭 축소 / 감사 / 격리 강화"로 간다. 사이드 채널은 *피해자가 결백하다*는 전제라 대응이 "구현을 상수시간으로 고치기 / 하드웨어 격리"로 간다. 같은 캐시 공격이라도 위협모델이 다르면 처방이 달라진다.
- **non-interference를 만족하는 실제 시스템이 존재하는가.** 사실상 없다. 자원을 공유하는 한 성능은 서로 간섭하고, 간섭은 곧 관측 가능한 신호다. 따라서 현실의 목표는 "제거"가 아니라 **"대역폭을 정책상 허용 가능한 수준 이하로 낮추기"** 다. TCSEC의 bps 기준선이 이 사고방식의 산물이라는 점을 확인했다.
- **1973년 논문이 지금도 유효한 이유.** 문제 설정 자체가 바뀌지 않았다. Lampson이 든 "CPU 사용량을 조절해 신호를 보낸다"는 예시가 클라우드 멀티테넌시에서 그대로 재현된다. 자원 공유의 층위만 훨씬 깊어졌을 뿐이다(캐시, 분기예측기, DVFS 주파수).
- **저장/타이밍 2분류의 모호함.** 캐시처럼 "상태는 저장인데 관측 수단은 시간"인 자원이 많아 판정이 갈렸다. 관측에 시계가 필요한지를 기준으로 통일했지만, 이 모호함 자체가 "저장 채널만 막으면 된다"는 식의 부분적 방어가 실패하는 이유이기도 하다.
